01 / Meet Robo·Boy

A web and desktop interface for controlling and visualizing ROS 2 robots.

Robo-Boy combines camera streaming, configurable control pads, 3D visualization, behavior-tree editing, TF inspection, and custom themes in one touch-friendly workspace. The web and desktop apps share the same React codebase; the Tauri desktop package is a thin shell and does not bundle ROS.

A

Operate

Drive and monitor a robot from a phone, tablet, laptop, or desktop webview.

B

Visualize

Inspect cameras, TF, laser scans, point clouds, poses, odometry, and URDF models.

C

Compose

Build reusable control pads and behavior trees without making a one-off dashboard.

D

Extend

Ship trusted, standalone ESM panels against a small, versioned, framework-neutral SDK.

!
Choose the right extension path.

A custom gamepad is an in-app JSON layout made from the built-in joystick, button, D-pad, toggle, slider, camera, plot, and heartbeat components. An external panel is independently built JavaScript, loaded through the Panel SDK. New gamepad component types are internal core development; they are not external SDK panels.

02 / Install & run

Two routes: the desktop app, or the browser stack.

The desktop app is the shorter one. It needs only the ROS services, so there is no certificate to create and no proxy to run. Choose the browser stack when Robo-Boy has to be opened from a phone, tablet, or another computer.

Desktop app and ROS stack

  1. 1

    Install the desktop app

    Linux.deb
    Linux.rpm
    macOS.dmg
    Windows.exe

    Each link resolves to the newest release. The macOS image is universal; the Linux packages are x86-64.

  2. 2

    Start the ROS services only

    git clone git@github.com:tessel-la/robo-boy.git
cd robo-boy
docker compose up -d --build ros-stack

    This one service supplies rosbridge, rosapi, and web_video_server. The web frontend, the proxy, and the certificate it would need are not started, because the desktop app talks to these ports directly.

    If the robot publishes message, service, or action types of its own, mount that workspace as well, or those topics arrive without a definition to read them with. See robot-specific interfaces.

  3. 3

    Open the app and connect

    Use Quick Connect when ROS runs on the same computer. When it runs elsewhere, open the advanced options, choose Host or IP, and enter that computer's hostname, LAN address, or VPN name.

    docker compose logs -f ros-stack
docker compose down

Robo-Boy never starts, stops, or bundles ROS. Run the stack on the robot computer instead of locally and only step 2 changes.

Browser, with the full Docker stack

Serving Robo-Boy to a browser adds two requirements the desktop app does not have: a browser needs HTTPS before it will grant a page a camera and other secure-context features, and the app and the robot services have to appear under one origin. Caddy supplies both, and a locally trusted certificate is what makes the first one work without warnings. You need Docker with Compose and mkcert.

  1. 1

    Clone and create a trusted local certificate

    git clone git@github.com:tessel-la/robo-boy.git
cd robo-boy
mkcert -install
mkdir -p infra/caddy/certs
mkcert \
  -key-file infra/caddy/certs/local-key.pem \
  -cert-file infra/caddy/certs/local-cert.pem \
  localhost 127.0.0.1 ::1 YOUR_HOST_IP

    Include the computer's LAN or VPN address as YOUR_HOST_IP when another device will open Robo-Boy.

  2. 2

    Start the stack

    docker compose up -d --build

    Open https://localhost, or https://YOUR_HOST_IP from a device on the same network. Every ROS and DDS setting has a default, so no environment file is needed for this configuration; add one only to select a robot workspace overlay.

  3. 3

    Stop or inspect the stack

    docker compose logs -f app
docker compose logs -f caddy
docker compose logs -f ros-stack
docker compose down

03 / Connect ROS 2

Robo-Boy talks to ROS through rosbridge.

The ROS stack supplies rosapi, rosbridge, and web_video_server. Robo-Boy discovers topics and interfaces after the shared ROSLIB WebSocket connects.

ConnectionWhat happensUse when
Quick Connect Uses the current web host's proxy routes. Desktop uses localhost. Robo-Boy and ROS services share a machine.
Domain ID Uses the current web host's proxy routes; DDS configuration belongs to the ROS container. The deployment owns ROS discovery settings.
Host or IP Uses the selected backend host for rosbridge, video, and mesh endpoints. The robot computer is elsewhere on the LAN or VPN.

On the web, Quick Connect normally resolves these through same-origin /websocket, /video_stream, /mesh_resources, and /ollama routes. Advanced Ports override the first three service ports. Tauri connects directly.

DDS and robot-specific interfaces

The ros-stack service uses host networking for DDS discovery. Every container that must discover the same graph needs compatible ROS_DOMAIN_ID, ROS_LOCALHOST_ONLY, and RMW_IMPLEMENTATION settings.

Robo-Boy reads a topic through the interface definition that describes it, and it only has the definitions present inside ros-stack. A robot with message, service, or action types of its own therefore needs its built workspace mounted there, or those topics appear in the graph and cannot be decoded. Mount the workspace's install directory under a unique path in a Compose override:

services:
  ros-stack:
    volumes:
      - /path/to/robot_ws/install:/overlay_ws/robot:ro
COMPOSE_FILE=docker-compose.yml:infra/compose/robot.yml docker compose up -d --build

Overrides for the bundled Aerostack and manipulator workspaces already exist under infra/compose/. A workspace built with colcon --symlink-install also needs its build and source directories mounted, since its installed files point back at them.

ROS_DOMAIN_ID=0
ROS_AUTOMATIC_DISCOVERY_RANGE=SUBNET
ROS_STATIC_PEERS=
RMW_IMPLEMENTATION=rmw_fastrtps_cpp
FASTDDS_BUILTIN_TRANSPORTS=UDPv4

A robot workspace overlay is selected by pointing Compose at one of the bundled override files, either in .env or on the command line. After changing overlays, recreate the service:

COMPOSE_FILE=docker-compose.yml:infra/compose/aerostack.yml
# or infra/compose/manipulator.yml
docker compose up -d --build --force-recreate ros-stack

06 / Panel SDK

Independent code. Small contract. Trusted boundary.

The Panel SDK is a type-only package. A panel exports one framework-neutral definition, runs in its own opaque-origin iframe, owns everything below the supplied DOM element, and receives only declared host services over a private channel. Robo-Boy does not scan node_modules or import panel source into its application build.

Robo-Boy core Catalog → verify → sandbox → broker

Owns metadata and integrity checks, workspace layout, iframe lifecycle, permission brokers, persistence, and tile-local errors.

+
External repository Source → ESM bundle → release

Owns dependencies, tests, manifest, immutable artifacts, and distribution policy.

=
Installed deployment Same-origin versioned assets

panels/installed.json lists only the releases packaged into that Robo-Boy deployment.

⚠
v2 minimizes access; it is not a hostile-code boundary.

Each panel runs without allow-same-origin, direct HTTP is blocked by sandbox CSP, and host services enforce manifest permissions. A panel can still consume CPU or misuse data explicitly granted to it, so install only reviewed artifacts.

The host owns tile creation, sizing, ordering, saved workspace layouts, and replacement. The panel owns only DOM below its mount element; v2 exposes no parent-page or layout-mutation API. Store panel configuration through context.storage, and keep framework/runtime dependencies inside the panel's own bundle.

Capability declarations

storageSupplies a 64 KiB, instance-owned JSON store.
networkSupplies credential-free brokered fetch and explicitly approved host endpoints constrained by permissions.network.
web-bluetoothDeclares Web Bluetooth use.
web-usbDeclares WebUSB use.
web-serialDeclares Web Serial use.
cameraDeclares camera/media capture.
microphoneDeclares microphone/media capture.

Permission declarations

{
  "capabilities": ["ros", "network"],
  "permissions": {
    "ros": {
      "selectTopic": true,
      "publish": ["/cmd_vel"],
      "services": ["/robot/reset"]
    },
    "network": {
      "origins": ["https://telemetry.example.com"],
      "hostEndpoints": ["videoStream"]
    }
  }
}

ROS and network capabilities require matching permission blocks. Static topic/service patterns are checked for every operation. selectTopic opens a trusted Robo-Boy picker and grants only the chosen topic to that tile; panels never receive the unfiltered graph. Brokered network requests omit ambient browser credentials and revalidate redirects.

07 / Lifecycle

One imported module can create many isolated tile instances.

1Discover

Fetch and validate registry JSON. No panel code runs.

→
2Sandbox

Verify SHA-256, create an opaque iframe, and transfer source over a private channel.

→
3Activate

Import the ESM in the sandbox and create one instance with brokered services.

→
4Mount

Render below the supplied HTML element.

→
5Pause

React to effective visibility through setActive.

→
6Unmount

Release every owned resource, deterministically.

What remounts a panel

  • The tile or host disappears.
  • The panel manifest/version changes.
  • A required ROS instance changes.
  • The user retries after a lifecycle error.

What unmount() must release

  • DOM and browser event listeners.
  • Timers, animation frames, and observers.
  • Brokered ROS subscriptions and pending requests.
  • Media streams, WebRTC, WebGL, and device connections.

setActive(isActive) is optional; mount and unmount are mandatory. Effective active state combines workspace activity, tile intersection, and document visibility. Removing the iframe terminates the panel realm even if cleanup fails.

Storage contract and limits 
interface RoboBoyPanelStorage {
  readonly schemaVersion: 1;
  readonly quotaBytes: number;
  get<T extends RoboBoyJsonValue>(key: string, fallback: T): T;
  set(key: string, value: RoboBoyJsonValue): void;
  remove(key: string): void;
  sizeBytes(): number;
}

Keys are 1–128 characters using letters, numbers, dots, underscores, or dashes. Values must be finite, acyclic, plain JSON no deeper than 20 levels. Each tile has a 64 KiB serialized quota.

    Implement src/index.ts

    import type {
  RoboBoyPanelContext,
  RoboBoyPanelDefinition,
} from '@tessel-la/roboboy-panel-sdk';

const activate = (context: RoboBoyPanelContext) => {
  let root: HTMLElement | null = null;
  let button: HTMLButtonElement | null = null;
  let count = context.storage?.get('greetings', 0) ?? 0;

  const renderCount = () => {
    if (button) button.textContent = `Send greeting (${count})`;
  };

  const sendGreeting = () => {
    count += 1;
    context.storage?.set('greetings', count);
    context.logger.info(`Greeting ${count} sent.`);
    renderCount();
  };

  return {
    mount(container: HTMLElement) {
      root = document.createElement('section');
      root.style.cssText = `
        height: 100%; display: grid; place-items: center;
        padding: 24px; box-sizing: border-box;
        color: var(--text-color, #f5f7fb);
        background: var(--background-secondary, #252b35);
      `;

      const content = document.createElement('div');
      content.style.textAlign = 'center';

      const heading = document.createElement('h2');
      heading.textContent = 'Hello from outside Robo-Boy';

      button = document.createElement('button');
      button.type = 'button';
      button.addEventListener('click', sendGreeting);
      renderCount();

      content.append(heading, button);
      root.append(content);
      container.replaceChildren(root);
    },

    setActive(isActive: boolean) {
      root?.toggleAttribute('data-inactive', !isActive);
    },

    unmount() {
      button?.removeEventListener('click', sendGreeting);
      root?.remove();
      button = null;
      root = null;
    },
  };
};

const definition: RoboBoyPanelDefinition = {
  apiVersion: '2.0.0',
  id: 'com.example.greeting',
  activate,
};

export default definition;

10 / Copy-and-adapt recipes

Patterns for real robot panels.

Panel API v2 brokers ROS as JSON operations. Panels do not receive ROSLIB, the rosbridge URL, or the complete graph; every request is checked against the manifest permissions.

ROS Subscribe to a topic 
import type { RoboBoyRosSubscription } from
  '@tessel-la/roboboy-panel-sdk';

let subscription: RoboBoyRosSubscription | null = null;

if (context.ros) {
  const selected = await context.ros.selectTopic({
    currentTopic: '/battery_state',
  });
  subscription = await context.ros.subscribe({
    topic: selected.name,
    messageType: selected.messageType,
    queueLength: 1,
    throttleMs: 100,
    compression: 'none',
  }, (message) => {
    renderBattery(message);
  });
}

// In async unmount():
await subscription?.unsubscribe();
subscription = null;

Declare capabilities: ["ros"] and permissions.ros.selectTopic: true. The complete graph stays in trusted Robo-Boy UI; the panel receives and is granted only the selected topic and message type.

ROS Publish a message 
await context.ros?.publish({
  topic: '/cmd_vel',
  messageType: 'geometry_msgs/msg/Twist',
  message: {
    linear: { x: 0.2, y: 0, z: 0 },
    angular: { x: 0, y: 0, z: 0 },
  },
});

Declare the exact publish path in permissions.ros.publish and match the robot's interface definition. For continuous controls, throttle publishing, cancel pending work, and deliberately publish a safe released/stopped state when the panel owns that responsibility.

STATE Expose settings and persist configuration 
import type { RoboBoyJsonObject } from
  '@tessel-la/roboboy-panel-sdk';

type Settings = { topic: string; compact: boolean };

const fallback: Settings = {
  topic: '/battery_state',
  compact: false,
};

const stored = context.storage?.get(
  'settings',
  fallback as unknown as RoboBoyJsonObject,
);
let settings = (stored as unknown as Settings) ?? fallback;

function save(next: Settings) {
  settings = next;
  try {
    context.storage?.set(
      'settings',
      next as unknown as RoboBoyJsonObject,
    );
  } catch (error) {
    context.logger.warn('Unable to persist settings.', error);
  }
}

v2 has no host-rendered settings pane. Render controls inside your tile, sanitize loaded data, keep secrets out of storage, and handle quota errors.

LIVE Pause expensive rendering when hidden 
let frame: number | null = null;
let active = context.viewport.getSnapshot().isActive;

const draw = () => {
  if (!active) return;
  renderLatestSample();
  frame = requestAnimationFrame(draw);
};

const stop = context.viewport.subscribe((snapshot) => {
  active = snapshot.isActive;
  if (active && frame === null) frame = requestAnimationFrame(draw);
  if (!active && frame !== null) cancelAnimationFrame(frame);
  if (!active) frame = null;
});

// In unmount():
stop();
if (frame !== null) cancelAnimationFrame(frame);

Use viewport width and height for compact layouts. Use setActive for coarse lifecycle changes and the viewport subscription when size or detailed visibility matters.

VIDEO Camera and WebRTC panels

For core ROS image topics, prefer the built-in Camera panel or a custom gamepad camera component. A transport-specific external panel can declare network with permissions.network.hostEndpoints: ["videoStream"], read context.network?.endpoints.videoStream, use context.network.fetch, and own its WebRTC lifecycle. The official WebRTC panel:

  • Discovers ready gateway paths below the restricted /webrtc/_discovery/paths resource.
  • Negotiates WHEP with the browser's native WebRTC API.
  • Stops statistics timers, aborts discovery, closes the remote WHEP session, and clears media on deactivate/unmount.
  • Keeps bearer credentials in memory; it never writes them to panel storage.

13 / Best practices & stability

Build against the contract, not the host implementation.

Public / versioned

Safe dependencies

  • panel-sdk/index.d.ts and API version 2.0.0.
  • The definition, lifecycle, brokered ROS/network, storage, runtime, connection, viewport, theme, and logger interfaces.
  • The manifest capabilities, permission blocks, and installed-registry contract documented for v2.
  • The reviewed CSS custom properties, used with your own fallbacks.
Internal / changeable

Do not couple to these

  • React components, hooks, application stores, and feature-module files.
  • MainControlView, ExternalPanelHost, loader/registry internals, or localStorage keys.
  • Built-in panel adapters and custom-gamepad implementation details.
  • Robo-Boy's bundled copy of ROSLIB, Three.js, or any other dependency, and its private endpoint map.

Own resources

Create clients inside the instance that cleans them up. Make unmount safe to call after partial startup and more than once.

Defend state

Version and sanitize your settings. Store only plain JSON. Keep live objects, handles, credentials, and large sample buffers in memory.

Respect activity

Stop decoding, polling, plotting, and device traffic while inactive. Design from a small tile upward using viewport snapshots.

Handle reconnects

Watch connection generation. Discard stale async results and re-establish brokered subscriptions after reconnects.

Keep releases lean

Bundle only what the panel needs. Shared host dependencies are deliberately not part of v2, and relative dynamic chunks are not supported.

Fail locally

Use the supplied logger, provide meaningful empty/error states, and allow exceptions to remain attributable to your versioned bundle.

14 / Troubleshooting

Start at the boundary that is failing.

Robo-Boy loads, but ROS never connects

Check docker compose logs ros-stack, confirm rosbridge listens on the selected/default port, and verify the web proxy or direct host is reachable. Every DDS participant must use compatible domain, discovery, and middleware settings.

The phone rejects HTTPS or browser device APIs

Regenerate the mkcert certificate with the machine's current LAN/VPN IP and trust the mkcert CA on the client device. Camera, Bluetooth, and similar browser APIs generally require a secure context.

Custom ROS messages are missing

Mount a built install workspace under /overlay_ws/<name>, recreate ros-stack, and inspect its logs for the activation line. Generated hooks may also require their original build/source paths.

A panel does not appear in Add panel

Normal dev and build use an empty tracked registry. Run a panel-aware command. Check ID uniqueness, manifest shape, compatibility ranges, same-origin versioned entry point, registry size, and the browser console for registry issues.

Local panel staging fails

Confirm the schema-v2 configuration names the local repository explicitly and its root resolves correctly on the host or through the approved root environment variable. Rebuild, regenerate the digest, and verify the manifest ID, API compatibility, capabilities, permissions, and integrity.

The tile says the panel could not start

Inspect the panel-prefixed console error. Common causes are an invalid default export, mismatched ID/API version, rejected integrity, unresolved runtime imports, sandbox startup failure, failure in activate/mount, or a denied capability/permission. Fix the artifact and publish/stage a new immutable version.

State fails to save

Declare storage; validate keys and plain JSON values; avoid cycles, non-finite numbers, deep nesting, and the 64 KiB per-instance limit. Browser storage is isolated by origin and can be unavailable or full.

Video, plots, or WebGL keep consuming resources

React to effective activity, unsubscribe high-rate topics, cancel animation frames, stop media tracks/timers, close peer/device connections, and dispose rendering resources in unmount.

15 / Known gaps

What the v2 SDK deliberately does not promise yet.

These are current platform boundaries found in the SDK, host loader, and project documentation—not hidden APIs to work around.

01

No automatic update or rollback

Compose provides authenticated preview/apply installation management, but there is no rollback UI, scheduled update policy, publisher revocation service, or garbage collector. CLI staging remains available for builds and Tauri.

02

Not a hostile-code boundary

The opaque-origin iframe prevents parent-page access and brokers host services, but a panel can still consume main-thread resources or misuse data explicitly granted to it. Install only reviewed artifacts.

03

No host settings surface

Panels render their own settings inside the tile. There is no standardized settings schema, secret store, notifications API, or application-level command surface.

04

Single-bundle releases

The installer rejects extra manifest assets until inventory metadata defines immutable URLs for every asset.

05

No shared runtime dependencies

Panel authors bundle any framework and runtime libraries themselves. This preserves independence but can duplicate code across panel sandboxes.

06

Integrity is not identity

SHA-256 detects drift but does not authenticate a publisher. Signing, inventory review policy, transactional rollback metadata, and revocation remain future hardening work.

07

No per-panel resource accounting

Lifecycle failures are tile-local and removing the iframe terminates its realm, but CPU-heavy synchronous code can still affect the main thread. Per-panel CPU and bandwidth limits remain future work.

08

ROS is a JSON broker

API v2 supports discovery, trusted topic selection, subscriptions, publishing, and service calls. Binary payloads, actions, and streaming service responses are not part of the contract.
